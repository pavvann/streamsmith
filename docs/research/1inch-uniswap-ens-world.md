## 1. Technology research

### 1.1 1inch — Aqua + SwapVM

**What Aqua is.** A registry of *virtual balances*, not a vault. LPs approve tokens once to `Aqua.sol`, then `ship(app, strategyBytes, tokens, amounts)` to allocate virtual balances to a strategy hash under an *app* contract; tokens stay in the LP wallet until a swap `pull()`s them. `dock()` withdraws. Strategies are immutable once shipped (change = dock + ship). Storage: `balances[maker][app][strategyHash][token]`. Apps inherit `AquaApp` (reentrancy lock per maker+strategy, `_safeCheckAquaPush`). The pitch: one wallet's capital backs many strategies simultaneously; only the strategy that actually executes pulls funds ("balance sufficiency" is enforced per strategy at swap time). Example app: `examples/apps/XYCSwap.sol` (constant product w/ callback).

**What SwapVM is.** A bytecode VM for programmable swaps. A maker's *order* = `maker + traits + program`. Programs are `[opcode:1B][argsLen:1B][args]` sequences executed by `ContextLib.runLoop`. Registers: `balanceIn, balanceOut, amountIn, amountOut` (+ fee accounting). Taker specifies one amount, VM computes the other. Two authorization modes: EIP-712 signature (isolated "dynamic balances" stored in SwapVM) or `useAquaInsteadOfSignature=true` (balances come from Aqua; the SwapVM router *is* the Aqua app). Router `quote()` (view) must equal `swap()`.

**Instruction families (src/instructions):** Balances (Static/Dynamic), LimitSwap(+FullAmount), XYCSwap, XYCConcentrate (CLMM range), PeggedSwap (StableSwap-like), Decay (Mooniswap virtual balances), DutchAuctionBalanceIn/Out, PiecewiseLinearScaleBalanceIn/Out, TWAPSwap, RequireMinRate/AdjustMinRate, OraclePriceAdjuster (Chainlink `latestRoundData`), BaseFeeAdjuster, FeeFlatIn/Out, FeeProtocol, Invalidators (Bit/TokenIn/TokenOut), ValidateSeriesEpoch (batch-cancel by epoch), Controls (Stop/Revert/Deadline/Salt), Jumps (Jump/JumpIfDirection/JumpIfTokenIn/Out), TokenValidators (OnlyTakerTokenBalanceNonZero — NFT/soulbound gate; ...Gte; ...SupplyShareGte; OnlyTxOrigin...), Whitelist (PrivateOrder, WhitelistCoequal, WhitelistSequential — time-phased unlock), Extruction (delegate registers to an external `IExtruction` contract).

**Maker hooks / taker callbacks.** MakerTraits has pre/post transfer-in/out hooks with target+data (Aqua Outcome Market used these for JIT borrowing from Euler EVC). TakerTraits has pre-transfer callbacks and `instructionsArgs` (dynamic data instructions consume via `ctx.tryChopTakerArgs`).

**Adding a custom opcode (the thing that wins).**
- Pick a slot in `src/libs/OpcodeList.sol` (enum banked by family; `0xd0–0xef` unallocated, `0xf0–0xff` reserved).
- Write `library MyOp { Opcode constant opcode = Opcode._d0; function build(...) ; function parse(bytes calldata) ; function exec(Context memory ctx, bytes calldata args) internal { ... } }`. `exec` may read/write `ctx.swap.*`, call `ctx.setNextPC`, `ctx.tryChopTakerArgs(n)`, use its own namespaced storage (see `StorageSlots.sol` + `SeriesEpochManager.sol` pattern), and must behave identically in `isStaticContext` (quote) vs swap.
- Add to a dispatcher (`contract MyOpcodes { function _runOpcode(Context memory, uint256 opcode, bytes calldata) internal virtual { if (opcode == MyOp.opcode.asU8()) MyOp.exec(ctx,args); else if ... } }`) and a router `contract MyRouter is SwapVM, MyOpcodes { constructor(aqua, weth, name, version) ... }`.
- Test with `CoreInvariants` (symmetry exactIn/exactOut, additivity profile, monotonicity, quote/swap consistency, balance sufficiency, liveness). `docs/PROGRAMS.md` says: provide analytical/empirical stability evidence, constrain dangerous parameter ranges in builders, document ordering constraints. Judges *will* look for this.
- Tooling reality: Hardhat 3 + viaIR; first compile ~7 min, then `yarn test` ~10s (771 Solidity tests). Foundry only needed for `snapshot:e2e` (anvil) and deploy scripts. `npm i @1inch/swap-vm @1inch/aqua` exist. TS: `@1inch/aqua-sdk` (ship/dock encoders, event parsers, addresses) and `@1inch/swap-vm-sdk` (Order/MakerTraits/TakerTraits, `ProgramBuilder(ixsSet)` for custom tables, `AquaProgramBuilder`, `AquaXYCAmmStrategy`). SDK release is recent (Aug 18 2026: aqua 0.3.1, swap-vm 0.4.1).
- License: `LicenseRef-Degensoft-SwapVM-1.1` / `Degensoft-Aqua-Source-1.1` (source-available, not MIT). Import as a dependency rather than vendoring; check the LICENSE before copying files into your repo.

**What "sophisticated DeFi position" means to them.** Buenos Aires prize text listed **Leverage, AMM, Lending, Options**. Past winners: *Aqua Outcome Market* (1st, BA) — novel pm-AMM invariant (Moallemi/Robinson) as a SwapVM instruction + maker hooks for JIT credit from Euler; *Aqua0* (4th) — cross-chain shared liquidity via LayerZero; *KSwap-VM* (3rd, Lisbon 2026) — K-framework formal semantics for SwapVM (found real bugs). Pattern: a **new curve or new instruction with a stability argument**, using Aqua's *shared liquidity* thesis visibly (same capital backing multiple strategies), demonstrated with real token transfers on a fork. Prediction markets are taken; leverage/lending/options are open.

**Internal branches worth knowing (what 1inch is thinking about):** `epoch-manager-opcode`, `depletion-fee-prototype`, `floating-range-amm-analysis`, `feature/Strict-Additive-Fees-Reinvested-Inside-Pricing`, `feature/base-fee-adjuster-normolization`. Don't clone these ideas, but "fees reinvested inside pricing" and "floating range" show they care about additivity and range-following.

First custom opcode with invariants tests passing: **~1 day**. Judges want: git history over the event, onchain transfers in the demo (fork OK), tests or UI showing the final position.

### 1.3 ENS — ENSv2 on Sepolia

**Architecture.** Hierarchical registries: a name is a chain of entries linked by `subregistry` pointers (`inigo` lives in the `montoya.eth` registry which is an entry in the `.eth` registry). `IRegistry { getSubregistry(label); getResolver(label); getParent() }`. Universal Resolver V2 walks root → down; **deepest resolver wins (longest-suffix)**, so a parent's resolver answers for subnames with no entry (**wildcard**, requires `IExtendedResolver`/ENSIP-10). **Namespace aliasing**: mount one registry under several parents (`x.montoya.eth` ≡ `x.wallet.eth`). Grace period 28 days. Each registered name is an ERC1155Singleton token with **mutable token IDs** (change on role updates / re-registration → index by labelhash).

**Enhanced Access Control (EAC).** Per resource (name) 32 regular + 32 admin roles packed as nybbles in a `uint256`; `ROOT_RESOURCE` (0) = master key; up to 15 holders per role per resource; `grantRoles/revokeRoles(resource, bitmap, account)` and `grantRootRoles/revokeRootRoles`; admin role = `role << 128`. Replaces fuses: revoke instead of burn (reversible while admin held; irreversible once role+admin both revoked). Hooks: `_getRoles`, `_onRolesGranted/Revoked` (registry regenerates token IDs), `_getSettableRoles` (registry blocks admin-role grants on names after registration).

**Permissioned Registry roles:** `ROLE_REGISTRAR 1<<0` (root), `ROLE_REGISTER_RESERVED 1<<4`, `ROLE_SET_PARENT 1<<8`, `ROLE_UNREGISTER 1<<12` (root or name), `ROLE_RENEW 1<<16`, `ROLE_SET_SUBREGISTRY 1<<20`, `ROLE_SET_RESOLVER 1<<24`, `ROLE_CAN_TRANSFER_ADMIN (1<<28)<<128` (admin-only; checked against owner), `ROLE_SET_URI 1<<36`, `ROLE_UPGRADE 1<<124`. `register(label, owner, subregistry, resolver, roleBitmap, expiry)` — expiry is absolute; owner=0 reserves. Three states AVAILABLE/RESERVED/REGISTERED. Operator approval (`setApprovalForAll`) inherits *all* owner roles on *all* names (no scoping).

**Subname "flavors" → role bitmaps (this is the prize rubric):**
- *Expiring*: set `expiry` < max; parent holds `ROLE_RENEW` on root.
- *Revocable*: parent keeps `ROLE_UNREGISTER` (root or that name).
- *Non-transferable*: omit `ROLE_CAN_TRANSFER_ADMIN` from `roleBitmap` (soulbound agent names).
- *Transferable*: include it.
- *Forever / no parent control*: `expiry = type(uint64).max` + parent *emancipates* its registry (revoke `ROLE_SET_RESOLVER/SET_SUBREGISTRY/UNREGISTER` + admins + `ROLE_UPGRADE` on ROOT) + lock canonical parent (`setParent` then revoke `ROLE_SET_PARENT`+admin).
- *Custom renderer*: `IRegistryURIRenderer.renderURI(registry, tokenId)` for on-chain SVG metadata.

**Permissioned Resolver.** Per-account UUPS proxy, records for many names. Roles: `ROLE_SET_ADDR 1<<0`, `ROLE_SET_TEXT 1<<4`, `ROLE_SET_CONTENTHASH 1<<8`, `ROLE_SET_PUBKEY 1<<12`, `ROLE_SET_ABI 1<<16`, `ROLE_SET_INTERFACE 1<<20`, `ROLE_SET_NAME 1<<24`, `ROLE_SET_ALIAS 1<<28` (root), `ROLE_CLEAR 1<<32`, `ROLE_SET_DATA 1<<36`, `ROLE_UPGRADE 1<<124`. **Per-key delegation**: `authorizeTextRoles(dnsName, key, account, grant)`, `authorizeDataRoles(...)`, `authorizeAddrRoles(dnsName, coinType, account, grant)`, `authorizeNameRoles(dnsName, roleBitmap, account, grant)`; resource = `keccak256(node, part)`. **Record aliasing**: `setAlias(fromDnsName, toDnsName)` (same resolver; only visible through UR `resolve()`; cycles > self OOG). `clearRecords(node)` bumps a version. `multicall`. Direct `text()/addr()` calls bypass aliasing.

**Sepolia deployments (docs.ens.domains/learn/deployments#sepolia-ensv2-beta):**
RootRegistry `0x8115186e8f2e0b0281e86ab91f0f48ba90364354` · ETHRegistry `0xbdc85dd5b15d7ecb354cd7cb6f2c50b4f2c4f0e2` · ETHRegistrar `0xa88553f454b77203b0d036a05c894d555eaaa2cc` · UniversalResolverV2 `0x4a1817d13e9cf196f471725176355c1234b63c70` · VerifiableFactory `0x10dc6333cdfe1fcef624c6e0a8221b91804cd7ef` · UserRegistryImpl `0x624a25d67b59d587752ebec8dded8827dae52050` · PermissionedResolverImpl `0x9eae5c2730a7dd16bdd1dee6421a1b91e3b0365e` · PublicResolverV2 `0xe7b9a25607e02da8145e4eb1836ca539e53f11f7` · MockUSDC `0x768f42455a2d082e23ceef7d51e5787c82d67a39` (free `mint(to, amount)`) · BatchRegistrar `0x8b16d15f3e51074d0e06f3cf4a0053f7cb92a7fb` · StandardRentPriceOracle `0x8914b66260eb8c4fff795650c3ae8cd335958987` · DefaultReverseRegistrarAdapter `0x7a84e241f862d73960d73c26d68c3c8f89f0b18f`. ### 1.4 World — Selfie Check, Sandbox, IDKit, AgentKit/AgentBook

**Selfie Check (Beta).** "Medium-assurance biometric credential using the device camera for liveness and facial similarity." Anyone with World App can do it (no Orb/passport). It proves a live person completed the check and, on return, that it's the *same* person (continuity); it does **not** give strict one-person-one-account, and returns "proof of the completed check, not a numeric Sybil or uniqueness score." 90-day inactivity window → re-verify. **Access-gated**: email `developers@toolsforhumanity.com` to enable the flag on your app. IDKit 4.x preset: `selfieCheckLegacy({ signal })` — uses **World ID 3.0** proofs (4.0 pending), so you get a `nullifier_hash` you can bind to a wallet/user id. Flow: `IDKit.request({ app_id, action, rp_context }).preset(selfieCheckLegacy({signal}))` → `connectorURI` (QR on desktop / deep link on mobile) → `pollUntilCompletion()` → POST the whole result to `https://developer.world.org/api/v4/verify/{rp_id}`. `rp_context` (`rp_id, nonce, created_at, expires_at, signature`) is signed server-side with `signRequest` from `@worldcoin/idkit-core/signing` using `RP_SIGNING_KEY`. Store nullifiers (hex → decimal, `NUMERIC(78,0)`).

**Sandbox.** Separate production-like backend + World App builds (iOS TestFlight, Android private Play track); "resettable accounts"; hot / cold / semi-cold user states; same-device (deep link) and cross-device (QR). Request via Developer Portal → "World ID Sandbox" (iOS/Android tabs) and `sandbox.access@toolsforhumanity.org`; prize page form `https://forms.gle/mqbaiwMvX5MzmKdY8`. Set `environment: "sandbox"` in IDKit; verify at the normal endpoint. Known gaps (good feedback-doc material): iOS semi-cold "Sign in vs Sign up" dead-end for invite codes; invite-code handling differs iOS/Android; sandbox proofs are non-production.

**AgentKit (Beta) + AgentBook.** `npm i @worldcoin/agentkit` (+ `@worldcoin/agentkit-cli`). AgentBook (`contracts/src/AgentBook.sol`): `register(agent, root, nonce, nullifierHash, proof[8])` verifies a World ID proof via `IWorldIDGroups.verifyProof(root, groupId, hash(agent,nonce), nullifierHash, EXTERNAL_NULLIFIER, proof)` and sets `lookupHuman[agent] = nullifierHash`; `getNextNonce(agent)`. Deployments: **World Chain (480)** `0xA23aB2712eA7BBa896930544C7d6636a96b944dA` (canonical; verifier default), **Base** `0xE1D1D3526A6FAa37eb36bD10B933C1b77f4561a4` (default relay `https://x402-worldchain.vercel.app`), **Base Sepolia** `0xA23aB2712eA7BBa896930544C7d6636a96b944dA` (`--network base-sepolia --manual`, no default relay; a minimal relayer example ships in `cli/examples/register-relayer.mjs`). Protocol: server returns 402 with `agentkit` extension (CAIP-122 challenge); agent signs with its wallet (EOA or ERC-1271/6492 smart wallet) and sends the `agentkit` header; server verifies + `lookupHuman`, then applies mode `free` / `free-trial{uses}` / `discount{percent,uses}`; **usage counters are per human per endpoint** (two agents of one human share the quota). Server: `@x402/hono` + `createAgentkitHooks({agentBook, storage, mode})`, `declareAgentkitExtension`, `agentkitResourceServerExtension`; `createAgentBookVerifier({contractAddress, client, rpcUrl})` lets you point at Base Sepolia. Client: `createAgentkitClient({signer}).fetch(url)`. Payment rails: World Chain USDC `0x79A02482A880bCE3F13e09Da970dC34db4CD24d1`, Base, Tempo, Arc built-in RPCs. Skills: `npx skills add worldcoin/agentkit agentkit-x402` / `integrate-agentkit`. Registration needs a real World App verification (Orb-group) — a team member with a verified World ID is required; whether AgentBook registration works from the Sandbox app is **unverified**.

**What judges want.** Both tracks: working app + Sandbox used for remote testing + a **feedback document** (docs/integration flow; Developer Portal navigation/search/discovery/debugging; Sandbox states, proof flows, test users, errors, edge cases; what was confusing/missing/broken). Selfie: treat it as a *risk/eligibility/fairness/continuity/abuse-prevention signal*. AgentKit: continuity-only; "durable human-backed agent authorization for access, commerce, rate limits, trust, continuity across services"; register/resolve via AgentBook.

**Time to first working thing:** IDKit + verify endpoint ~half a day *after* access lands (the gating is the schedule risk). AgentKit server+client on Base with the hosted relay: half a day; on Base Sepolia with your own relayer: ~1 day.

## 2. Idea seeds

Legend: **[SAFE]** clearly qualifies with bounded risk · **[AMBITIOUS]** stretch but demoable · **[HOLY SHIT]** if it works, it wins.

### 1. HumanPass Pool — Selfie-gated v4 liquidity & trading [SAFE]
**Pitch.** A soulbound "HumanPass" is minted to a wallet after a Selfie Check (backend verifies the IDKit result at `/api/v4/verify/{rp_id}`, signs an EIP-712 attestation binding `nullifier → wallet`; the contract mints one pass per nullifier and re-attests every 90 days, mirroring Selfie Check's inactivity window). A v4 hook (`beforeSwap` + `beforeAddLiquidity`, optionally as an `IAllowlistChecker` for the Permissioned Pools stack) requires the *initiator* to hold a fresh pass and enforces a per-human daily volume cap (nullifier-keyed) — a bot-farm and wash-trading dampener for a new token's first week.
**Tracks.** World Selfie Check (Selfie = eligibility + abuse-prevention signal; Sandbox for remote test; feedback doc), Uniswap ($1K: new v4 hook; FEEDBACK.md).
**Wow moment.** Two wallets try the same swap on Sepolia: the bot reverts `NotHuman()`, the Selfie-verified one fills; then the *same human* opens a second wallet and hits the per-human cap because the cap keys on the nullifier, not the address.
**Hardest risk.** Selfie Check + Sandbox access latency; the hook sees the router as `sender`, so you gate `hookData`/`tx.origin`-style initiator identity (use the Permissioned Pools pattern where the router is the approved wrapper and checks the user).
**Load-bearing combos.** Graph (index pass mints + hook rejections into a Standardized-schema subgraph for a "human volume share" dashboard). Chainlink CRE Confidential Workflows (run the Selfie verify + attestation signing inside a TEE handler so `RP_SIGNING_KEY` never leaves the enclave — a real reason for confidentiality).

### 2. AgentNS — ENSv2 agent namespaces as the permission layer for agent payments [SAFE core / AMBITIOUS edges]
**Pitch.** An org name (`acme.eth` on Sepolia) deploys a `UserRegistry`; every agent gets an **expiring, non-transferable** subname (`ops-bot.acme.eth`, bitmap without `ROLE_CAN_TRANSFER_ADMIN`, 30-day expiry, parent keeps `ROLE_UNREGISTER`). Each agent's records live in the org's Permissioned Resolver with **per-key delegation**: the agent wallet may only write `agent-endpoint[mcp]`/`agent-context` (ENSIP-26) via `authorizeTextRoles`; the treasury alone writes `agent-budget`, `agent-allowed-services`, `agent-human` (AgentBook humanId); `agent-registration[<erc7930 8004 registry>][id]` (ENSIP-25) links to the ERC-8004 IdentityRegistry on Sepolia. A small `x402`-gated service resolves the *caller's* name via UR V2, reads policy records, and only serves if budget/allowlist pass. Revoking one role, letting the name expire, or `unregister` = the agent is fired everywhere at once. Namespace aliasing (`*.agents.acme.eth` ≡ `*.acme.xyz`) shows the org can re-brand without re-issuing identities.
**Tracks.** ENS (hierarchical registry, own subname registry, EAC delegation, Permissioned Resolver per-key roles, aliasing, expiring/revocable/non-transferable — and literally "agents as namespaces"). Cross-cluster: **Hedera** x402 (ERC-8004/on-chain identity = "extra points"), **Arc** Agent Stack (agents with wallets + decision logic tied to policy records), **Graph** (Agent0/ERC-8004 standardized subgraph + your ENS records → composable "who is this agent" query), **Ledger** (agent keys live in Key Ring; ENS record edits that escalate permission require device confirmation).
**Wow moment.** Live: treasury edits `agent-budget` on `ops-bot.acme.eth` → the agent's very next paid request is refused with the ENS name in the 402 body; then `unregister` and the agent disappears from resolution entirely.
**Hardest risk.** ENSv2 contracts are beta; token IDs mutate on role changes (never cache them); resolving on Sepolia from your backend needs viem ≥ 2.35 with UR V2 override; ENSIP-19 reverse resolution on v2 Sepolia for "caller → name" is less battle-tested — fall back to the agent presenting its name and you verifying `addr(name) == signer`.
**Note.** This is the identity substrate the whole "agent payments" side of the hackathon (Hedera x402, Arc, Graph, Ledger, Bazantic) can sit on; pairs naturally with #6.

### 3. Aqua Options Desk — covered calls/puts as SwapVM programs on *shared* liquidity [HOLY SHIT]
**Pitch.** An option is "the right to swap at strike K until expiry T." Express it as two SwapVM orders backed by one Aqua balance: (a) a **premium order** — 1D limit order where the buyer pays USDC premium; `DutchAuctionBalanceIn` decays the premium toward expiry (theta for free), `InvalidateBit` makes it one-shot, and a *post-transfer-in maker hook* writes `optionSold[optionId] = buyer` into a small `OptionBook`; (b) an **exercise order** — `RequireOptionHolder(optionId)` (new opcode: reads OptionBook and checks `ctx.query.taker`; consumes nothing) + `Deadline(T)` + `StaticBalances(strike)` + `LimitSwapFullAmount` (+ `InvalidateBit`). The LP ships 10 ETH **once** into Aqua and sells calls at three strikes; only the in-the-money exercise can ever `pull()` — Aqua's balance-sufficiency does the netting. Add `OraclePriceAdjuster`/Chainlink for "auto-exercise only if ITM" and `ValidateSeriesEpoch` so the writer can cancel an unsold series in one tx. Ship a TS `OptionsStrategy` on top of `ProgramBuilder` with a custom opcode table, plus `CoreInvariants` tests (symmetry, quote/swap consistency; monotonicity skipped for fixed-rate legs — documented).
**Tracks.** 1inch ("Options" is explicitly on their list; custom opcode; official Aqua contracts on a Base/mainnet fork; onchain transfers in demo).
**Wow moment.** One `ship()`, three calls sold to three takers, block-timestamp warp to expiry on the fork, one exercise fills at strike while the others revert `Deadline`, and the LP's wallet shows the premium income — with the ETH never having left the wallet until exercise.
**Hardest risk.** Quote/swap divergence: the premium leg's hook writes storage during `swap` but not `quote` (documented divergence for Extruction; keep the write in the *hook*, not the opcode). Also a maker-side hook + custom opcode + Aqua mode in one program is more surface than a hackathon usually survives — build the exercise leg first (it alone is a valid "American option" position).
**Load-bearing combos.** Chainlink (Price Feeds via the existing opcode; not CRE), Graph (index `Shipped/Swapped/Docked` to render open interest by strike), Uniswap (hedge delta on v4 Sepolia via Trading API — optional).

### 4. Fair-Fill — a `OnlyHumanTaker` opcode with per-human caps inside an Aqua Dutch auction [AMBITIOUS]
**Pitch.** A token sale/liquidation as a SwapVM program: `DutchAuctionBalanceOut` (price improves over time) + `OnlyHumanTaker(registry)` (new opcode: `humanId = AgentBook.lookupHuman(taker)` or `HumanPass.nullifierOf(taker)`; revert if 0) + `PerHumanCap(maxOut)` (new opcode with storage keyed by `(orderHash, humanId)` that clamps `amountOut` and records fills). Result: a Sybil-resistant fair distribution where 50 bot wallets can't front-run humans and one human with five wallets is still capped as one human. Fork **Base mainnet**: canonical Aqua + AgentBook (`0xE1D1…`) coexist there, so a real registered agent/human resolves on the fork.
**Tracks.** 1inch (custom opcodes; Aqua-backed; onchain transfers on fork). World Selfie Check if the gate is a Selfie-backed pass (fairness/abuse-prevention signal), or World AgentKit if you have an existing project to extend (continuity).
**Wow moment.** Two takers race the same Dutch auction on the fork; the unregistered wallet reverts, the human-backed one fills, and a second wallet controlled by the same human gets `CapExceeded(humanId)`.
**Hardest risk.** `PerHumanCap` writes storage in swap and must read-only in quote — `isStaticContext` branching is exactly the pattern 1inch warns about; test `quote==swap` explicitly. AgentBook on the fork holds real registrations, but you need a registered address whose key you control (register your own on Base mainnet: gasless relay, needs one Orb-verified human).
**Combos.** Graph (Agent0 subgraph to show which agents are human-backed), Arc (settle the sale in USDC on Arc via CCTP — a stretch).

### 5. V4-Anchored Aqua Market Maker — Aqua liquidity that follows Uniswap v4's price and hedges on it [HOLY SHIT]
**Pitch.** A `V4PriceAnchor` opcode reads `StateView.getSlot0(poolId)` for a v4 pool and sets the program's *effective* mid to the v4 sqrtPrice ± a configurable spread (implemented by scaling `balanceIn/balanceOut` before an `XYCConcentrate` or `LimitSwap` leg — the same trick `DutchAuction*` uses). The LP's Aqua capital becomes passive, oracle-free liquidity that never quotes stale vs. the deepest venue, but takes less toxic flow because of the spread. A maker **post-transfer-out hook** then hedges the fill on the v4 pool in the same tx (JIT delta hedging), turning the position into a spread-capturing market maker. Runs on a **Base mainnet fork** where both Aqua and v4 exist.
**Tracks.** 1inch (novel opcode + hook, Aqua-backed, transfers on fork). Uniswap (v4 integration — reads + swaps against PoolManager; FEEDBACK.md on StateView/V4Quoter DX).
**Wow moment.** Move the v4 pool with a big swap; the very next Aqua quote moves with it; a taker fills; the hedge lands on v4 in the same transaction; LP inventory is flat.
**Hardest risk.** Same-block price manipulation (read v4 slot0, push it, fill Aqua at a bad price) — you need a TWAP/observation guard or a cap on per-block deviation (`maxDecay`-style parameter), and this is exactly the "stability argument" 1inch asks for. Also the hedge hook must not touch VM registers (fine — hooks run after `runLoop`).
**Combos.** Graph (two protocols, one query: Aqua fills vs v4 mid), Chainlink Price Feeds as a sanity band.

### 6. HumanRate — Selfie-backed, per-human metering for x402 agent APIs [AMBITIOUS]
**Pitch.** AgentBook requires Orb; most humans don't have one. HumanRate is an "AgentBook-lite": a human does a **Selfie Check** in Sandbox, the backend verifies and issues a `humanId` (nullifier), and the human binds N agent wallets under it (signed binding) into a Sepolia `HumanBook` contract (same `lookupHuman(agent)` interface as AgentBook, so `@worldcoin/agentkit`'s verifier can be pointed at it via `contractAddress`). An x402 middleware then rate-limits and prices **per human, not per wallet**: 20 free calls/day per human across all their agents, then pay. Continuity: a returning human re-passes Selfie Check and keeps their quota history (Selfie's actual guarantee). This is the "Selfie Check as a sybil/abuse signal in an agent economy" thesis made concrete.
**Tracks.** World Selfie Check (risk/abuse-prevention/continuity signal; Sandbox; feedback doc). Cross-cluster: **Hedera** x402 service behind Blocky402 (the metered service), **Arc** Agent Stack (the consuming agents pay USDC on Arc), **Graph** AI (x402 pay-per-query Subgraph MCP tooling is exactly a metered agent service), **Bazantic** (x402/MPP gateway + recipe), **ENS** (#2: each bound agent gets a subname; `agent-human` record = humanId).
**Wow moment.** A human's three agents share one quota bar on screen; a fourth *unbound* agent is 402'd immediately; the human re-runs Selfie Check on a fresh phone (semi-cold sandbox state) and the quota bar is still theirs.
**Hardest risk.** Selfie Check is medium-assurance and World says it isn't a uniqueness score — you must frame it honestly as *friction + continuity*, not Sybil-proof, and pair it with AgentBook when available (tiered trust: Orb-backed > Selfie-backed > none). Sandbox access timing.

### 7. PolicyHook — v4 swaps governed by ENSv2 records [AMBITIOUS]
**Pitch.** A v4 hook on Sepolia that, in `beforeSwap`, reads the initiator's ENSv2 name (passed in `hookData`, verified by `addr(name) == initiator` through UR V2) and enforces policy from resolver records: `swap-limit-daily`, `allowed-pools`, `human-backed`. Because the org's Permissioned Resolver lets only the treasury write those keys while the agent can only write its own `agent-endpoint` keys, an agent literally cannot raise its own limit. Pair with a dynamic fee: verified-human names pay a lower LP fee (`afterInitialize` dynamic fee flag).
**Tracks.** Uniswap (hook), ENS (EAC per-key delegation, Permissioned Resolver, subnames as agent identity — ENSv2 is load-bearing, not cosmetic).
**Wow moment.** Edit one text record in the ENS app on Sepolia; the agent's next swap reverts with the policy key in the error.
**Hardest risk.** On-chain resolution gas inside a swap (UR V2 `resolve` walks the tree; keep names shallow, consider caching `name → node → resolver` per pool in the hook) and the "who is the swapper" problem (router = sender).
**Combos.** Ledger (device confirmation to change policy records), Graph (index policy changes vs swaps).

### 8. Aqua Credit Line — lending as a two-leg SwapVM position with time-accruing rate [HOLY SHIT]
**Pitch.** Lender ships USDC into Aqua once. **Borrow leg**: borrower (whitelisted via `WhitelistCoequal` or `OnlyTakerTokenBalanceNonZero(creditNFT)`) swaps collateral (WETH) → USDC at a haircut (`StaticBalances` at 70% LTV, `OraclePriceAdjuster` w/ Chainlink to anchor), and a new `OpenLoan` opcode records `(borrower, principal, t0)` in loan storage. **Repay leg**: `RepayLoan` opcode computes owed = principal × (1 + r·(t−t0)) (piecewise-linear via `PiecewiseLinearScaleBalanceIn`-style math) and sets the reverse-swap rate so the borrower gets their exact collateral back for exactly that amount; `Deadline` = maturity; after maturity a **liquidation leg** (`DutchAuctionBalanceOut` on the collateral, open to anyone) becomes valid via `ValidateSeriesEpoch` flip. Same USDC can back several credit lines; balance sufficiency limits total outstanding.
**Tracks.** 1inch ("Lending" is on their list; multiple custom opcodes; Aqua shared liquidity is the point; fork demo with transfers).
**Wow moment.** Borrow, warp 30 days, repay exactly the accrued amount and watch the collateral return; then a second borrower defaults, epoch flips, and a liquidator buys the collateral in a Dutch auction — all against one shipped balance.
**Hardest risk.** Interest math must round toward the maker and stay exactIn/exactOut symmetric; three coordinated orders sharing storage is real protocol design — scope to borrow+repay first, liquidation as stretch.
**Combos.** Chainlink Price Feeds; Graph indexing; Privy B2B (org wallets as lenders with policy approvals) is plausible but bolt-on.

### 9. Verified-Human CCA — a fair launch where only humans bid, one allocation per human [SAFE → AMBITIOUS]
**Pitch.** Deploy a token with UERC20Factory on Sepolia and launch it through the Liquidity Launcher/CCA with a custom **`IValidationHook`** that (a) requires the bidder to hold a HumanPass (#1) or resolve in AgentBook (Base Sepolia) and (b) caps cumulative bid budget per `humanId`. Post-auction, the migrated v4 pool carries the HumanPass hook for the first 72h. Optional ENSv2 flourish: every allocation is receipted as an **expiring, non-transferable** subname `0x…-allocation.<token>.launch.eth` whose resolver records hold the claim amount (the Permissioned Resolver's data records), so "who got what" is public and human-readable.
**Tracks.** Uniswap (CCA validation hook + LBP hook — two integration points; strong FEEDBACK.md material since CCA docs are thin on hooks). World Selfie Check (fairness/anti-bot signal). ENS (subnames as receipts — moderately load-bearing).
**Wow moment.** A scripted bot fires 50 bids from 50 wallets and every one reverts in the hook; five sandbox humans clear at one price; the pool goes live human-only.
**Hardest risk.** CCA factory must actually be deployed on your testnet (canonical CREATE2; deployable by anyone but that's an extra day); the hook interface/ERC-165 (CIP-1) details need to be read from the repo's `src/periphery/validationHooks` examples.

### 10. Continuity combo — retrofit AgentKit + ENSv2 into a project you already have [SAFE, only if you have a prior repo]
**Pitch.** If any teammate owns an existing agent/bot/x402 API repo (even a small one with pre-event commits), register it as a Continuity project and: add `@worldcoin/agentkit` hooks (`free-trial` for human-backed agents, `discount` mode requires wiring `verifyFailureHook` to the facilitator), resolve agents through AgentBook, and give each agent an ENSv2 subname with delegated record roles (#2). Document before/after clearly.
**Tracks.** World AgentKit Continuity ($3.5K, few competitors because continuity-only), ENS continuity ($500), Uniswap continuity ($1K×2) if the project swaps via the Trading API, 1inch continuity ($2K) if it already touches Aqua (unlikely).
**Wow moment.** The existing product's paywall drops for a human-backed agent and stays up for a bot, with zero changes to the agent's HTTP client (`agentkit.fetch`).
**Hardest risk.** Eligibility: ETHGlobal's continuity rules need documented pre-existing work; only in-event work is judged. Registration to AgentBook needs an Orb-verified human on the team.

**How I'd pick (1–3 people, 12 days):** one **1inch-first** build (#3 Options Desk or #5 V4-Anchored MM; #8 if you love lending) as the primary $2.5K shot, plus the **identity stack** (#2 AgentNS + #6 HumanRate) which qualifies for ENS, World Selfie, and is load-bearing for Hedera x402 / Arc / Graph / Bazantic in the other clusters. #1/#9 are the cheapest way to add Uniswap's $1K on top of the World work. ## 3. Traps and non-obvious things

1. **No Aqua/SwapVM testnet; the live router runs only the Aqua opcode subset; full SwapVM needs Fusaka (transient storage).** Plan for `anvil --fork-url` of Base or mainnet, redeploy your own router, and say so in the README. Hardhat 3 does not auto-load `.env` (config variables/keystore); first compile ~7 minutes (viaIR). The repos are **source-available (Degensoft license), not MIT** — depend on the npm packages, don't vendor and re-license. 1inch demands *real* commit history across the event.
2. **Quote/swap consistency is a first-class invariant.** Any opcode that writes storage must not diverge between `isStaticContext=true` (quote) and swap; put side effects in maker hooks, keep opcodes deterministic, and ship `CoreInvariants` tests. 1inch also asks for a written stability/ordering argument in `PROGRAMS.md` style — write a short design note.
3. **ENSv2: Sepolia only, "not yet final."** Token IDs change on role changes (index by labelhash); admin roles on a name can only be set at registration; operator approval is all-or-nothing; max 15 holders per role; aliasing only works through UR `resolve()` (direct `text()` returns empty) and alias cycles OOG; viem must be ≥ 2.35 *and* pointed at UR V2 `0x4a1817d13e9cf196f471725176355c1234b63c70` on Sepolia; registration needs MockUSDC mint + 60s commit-reveal; `ens-cli` is experimental (still worth trying for the "agent-native" story + feedback).
4. **World: three separate gates you don't control the timing of** — Selfie Check beta flag (email), Sandbox tester invite (portal + email), and the ETHGlobal sandbox form. Request all today. Selfie Check uses the *legacy* World ID 3.0 preset and is explicitly not a uniqueness guarantee — write the pitch as risk/continuity signal or judges will ding it. **AgentKit is Continuity-only.** AgentBook needs an Orb-verified human to register; Base Sepolia has no relay (run the example relayer). The **feedback document is a hard requirement for both World tracks** — start it on day 1 and log every papercut.
5. **Uniswap is $1K flat and audits missing FEEDBACK.md/form submissions.** Hooks are immutable per pool and need address mining; "a hook doesn't get frontend routing." CCA is canonical-CREATE2 but confirm it's on your testnet. Use `uniswap-ai` skills and critique them in FEEDBACK.md — the Foundation clearly wants that signal.
6. **Chain topology is fragmented:** Aqua = mainnet fork (Base/ETH); ENSv2 = Ethereum Sepolia; AgentBook = World Chain / Base / Base Sepolia; v4 = Sepolia/Base Sepolia; ERC-8004 = Sepolia + Base Sepolia. You cannot fork two chains into one anvil. Design the demo so the backend does cross-chain *reads* (ENS on Sepolia, AgentBook on Base Sepolia) while the money moves on one chain, and draw that in the architecture diagram.
7. **Continuity tracks** (1inch $2K, Uniswap $2K, ENS $500, World AgentKit $3.5K) require registering as a Continuity project with documented pre-existing work — decide on day 1 whether you have a qualifying repo; you can't retro-fit that.
